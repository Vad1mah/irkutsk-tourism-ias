# Выбор ORM: сравнительный анализ

## Критерии выбора

При выборе ORM для ИАС мониторинга туристической активности учитывались: поддержка асинхронного ввода-вывода (async/await), совместимость с PostgreSQL 16, наличие системы миграций, типизация (type hints), производительность batch-операций (upsert при массовом импорте данных парсеров), зрелость экосистемы и качество документации.

## Рассматриваемые альтернативы

### Сравнительная таблица

| Критерий | SQLAlchemy 2.0 | Tortoise ORM | asyncpg (raw SQL) | Peewee | Django ORM |
|----------|---------------|--------------|-------------------|--------|------------|
| Async-поддержка | Нативная (asyncio extension) | Нативная | Нативная | Нет | Ограниченная (Django 4.1+) |
| PostgreSQL-драйвер | asyncpg / psycopg3 | asyncpg | asyncpg (прямой) | psycopg2 | psycopg2 / psycopg3 |
| Система миграций | Alembic (автогенерация) | Aerich | Ручная | peewee-migrate | Встроенная |
| Типизация | mapped_column + Mapped[T] | Аннотации полей | Нет (raw SQL) | Нет | Ограниченная |
| Batch upsert | `on_conflict_do_update` | `bulk_create` (ограниченный) | `INSERT ... ON CONFLICT` | Нет нативного | `bulk_create` (Django 4.1+) |
| Query Builder | 2.0-style (select, where) | QuerySet (Django-like) | Нет (строки SQL) | Fluent API | QuerySet |
| Паттерн Unit of Work | Да (Session) | Да | Нет | Нет | Да |
| Связь с FastAPI | Через Depends (DI) | Нативная интеграция | Ручная | Ручная | Через django-ninja |
| Документация | Обширная (20+ лет) | Средняя | Минимальная (API ref) | Средняя | Обширная |

### Анализ альтернатив

**SQLAlchemy 2.0 async** предоставляет полноценную асинхронную работу через `AsyncSession` и `AsyncEngine` с драйвером asyncpg. Стиль запросов 2.0 (`select(Model).where(...)`) обеспечивает типобезопасность и автодополнение в IDE. Система миграций Alembic поддерживает автогенерацию на основе diff моделей, что критично при эволюции схемы БД. Декларативное описание моделей через `mapped_column` и `Mapped[T]` обеспечивает полную совместимость с mypy и Pydantic.

**Tortoise ORM** — async-нативный ORM, вдохновлённый Django ORM. Имеет более простой API (QuerySet), но уступает SQLAlchemy по зрелости экосистемы и гибкости. Система миграций Aerich менее стабильна, чем Alembic. Ограниченная поддержка сложных SQL-конструкций (CTE, оконные функции) может стать проблемой при аналитических запросах.

**asyncpg (raw SQL)** обеспечивает максимальную производительность за счёт прямого доступа к драйверу, но требует ручного управления SQL-запросами, отсутствия абстракции моделей и ручной системы миграций. Для проекта с 5 ORM-моделями и 59 endpoints это создаёт избыточную сложность сопровождения.

**Peewee** — компактный синхронный ORM. Отсутствие async-поддержки делает его непригодным для FastAPI-приложения, где все I/O-операции выполняются асинхронно. Использование `run_in_executor` для каждого запроса создаёт накладные расходы на управление потоками.

**Django ORM** — зрелая система с встроенными миграциями, но жёстко связана с фреймворком Django. Интеграция с FastAPI через django-ninja возможна, но создаёт архитектурную зависимость от двух фреймворков одновременно. Async-поддержка появилась в Django 4.1 и остаётся менее зрелой, чем в SQLAlchemy 2.0.

## Обоснование выбора

**SQLAlchemy 2.0 с asyncpg** выбран по следующим основаниям:

1. **Async-нативность**: `AsyncSession` и `AsyncEngine` обеспечивают неблокирующую работу с PostgreSQL, что критично для FastAPI-приложения с SSE-стримами и параллельными запросами к ML-моделям.

2. **Типизация**: декларативные модели с `Mapped[T]` и `mapped_column` обеспечивают статическую проверку типов, автодополнение в IDE и совместимость с Pydantic-схемами через `.model_validate()`.

3. **Миграции**: Alembic с автогенерацией на основе diff ORM-моделей — индустриальный стандарт, поддерживающий downgrade и ветвление миграций.

4. **Batch-операции**: `insert().on_conflict_do_update()` обеспечивает эффективный upsert при массовом импорте данных из парсеров (101Hotels, Xotelo) без N+1 проблем.

5. **Зрелость**: 20+ лет развития, обширная документация, активное сообщество и совместимость с основными инструментами экосистемы Python (Alembic, FastAPI, Pydantic, pytest).

ORM-модели проекта: `Hotel`, `HotelStatistic`, `Event`, `QueryHistory`, `Forecast` — используют FK-связи, CHECK-ограничения и автоматическое обновление `updated_at` через `server_default`.
