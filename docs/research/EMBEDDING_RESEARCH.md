# Выбор модели эмбеддингов: сравнительный анализ

## Критерии выбора

При выборе модели эмбеддингов для RAG-компонента ИАС учитывались: качество представления текстов на русском языке, доступность API из Российской Федерации без VPN, размерность вектора и совместимость с ChromaDB, наличие интеграции с LangChain, стоимость и лимиты API, а также латентность запросов.

## Рассматриваемые альтернативы

### Анализ альтернатив

**GigaChat Embeddings** — модель эмбеддингов от Сбера, оптимизированная для русскоязычных текстов. Обучена на корпусах русского языка, что обеспечивает лучшее семантическое представление доменной лексики (туристическая терминология, географические названия Иркутской области). Доступна через Sber API без VPN из РФ, что гарантирует стабильную работу системы. Интеграция через `langchain-gigachat` с классом `GigaChatEmbeddings`.

**sentence-transformers** (Hugging Face) — семейство open-source моделей для генерации эмбеддингов. Мультиязычные модели (`paraphrase-multilingual-MiniLM-L12-v2`, `multilingual-e5-large`) поддерживают русский язык, но уступают специализированным моделям на русскоязычных бенчмарках. Требуют self-hosting на GPU для приемлемой латентности; на CPU (без GPU) — ~500 мс на запрос, что создаёт задержки при индексации массива документов. Преимущество — отсутствие зависимости от внешнего API.

**Mistral Embed** — модель эмбеддингов от Mistral AI с размерностью 1024. Мультиязычная, доступна из РФ без VPN. Однако тарификация по токенам создаёт затраты при массовой индексации документов (описания отелей, события, прогнозы). Качество на русском языке ниже, чем у GigaChat Embeddings, вследствие фокуса обучения на английском и французском языках.

**OpenAI Embeddings** (`text-embedding-3-small`, `text-embedding-3-large`) — промышленный стандарт с высоким качеством на мультиязычных бенчмарках. Размерность 1536 обеспечивает детальное представление, но увеличивает потребление памяти ChromaDB. Основной недостаток — недоступность API из РФ без VPN, что создаёт зависимость от сетевой инфраструктуры и снижает надёжность продуктивной среды.

**E5 / BGE (open-source)** — семейство open-source моделей от Microsoft (E5) и BAAI (BGE). Мультиязычные варианты (`multilingual-e5-large-instruct`, `bge-m3`) показывают конкурентные результаты на бенчмарках MTEB. Аналогично sentence-transformers, требуют self-hosting и GPU. Модель `bge-m3` поддерживает dense + sparse + multi-vector retrieval, но сложность настройки избыточна для проекта с ~1000 документов в ChromaDB.

## Обоснование выбора

**GigaChat Embeddings** выбраны по следующим основаниям:

1. **Русскоязычная оптимизация**: модель обучена на корпусах русского языка, что обеспечивает лучшее семантическое представление туристической терминологии, географических названий и описаний достопримечательностей Иркутской области по сравнению с мультиязычными моделями.

2. **Доступность из РФ**: Sber API доступен без VPN и прокси, что гарантирует стабильную работу RAG-компонента в продуктивной среде. В отличие от OpenAI, отсутствует риск блокировки.

3. **Корпоративные credentials**: доступ через сертификат авторизации Сбер ID, что не создаёт финансовых затрат при использовании в рамках учебного проекта (бесплатный тариф для разработчиков).

4. **LangChain-интеграция**: класс `GigaChatEmbeddings` из пакета `langchain-gigachat` обеспечивает совместимость с ChromaDB через стандартный интерфейс `Embeddings`, что позволяет заменить модель без изменения кода индексации и поиска.

5. **Размерность 1024**: оптимальный баланс между качеством представления и потреблением памяти ChromaDB — при ~1000 документов в векторной базе размер индекса остаётся в пределах оперативной памяти.

Для обеспечения отказоустойчивости в `chroma_service.py` реализован fallback-механизм: при недоступности GigaChat API система переключается на `sentence-transformers` (`paraphrase-multilingual-MiniLM-L12-v2`), загружаемый локально на CPU.
