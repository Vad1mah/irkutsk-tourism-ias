# Выбор фреймворка AI-агентов: сравнительный анализ

## Критерии выбора

При выборе фреймворка для реализации AI-агентов ИАС учитывались: поддержка графового представления логики агента (state machine), интеграция с tool calling (вызов инструментов), поддержка SSE-стриминга для real-time ответов, сохранение контекста между обращениями (memory), возможность маршрутизации между специализированными агентами, а также совместимость с несколькими LLM-провайдерами (Mistral, GigaChat, Groq).

## Рассматриваемые альтернативы

### Сравнительная таблица

| Критерий | LangGraph | LangChain AgentExecutor | CrewAI | AutoGen | Custom loop |
|----------|-----------|------------------------|--------|---------|-------------|
| Архитектура | Граф состояний (StateGraph) | Цепочка (ReAct loop) | Ролевые агенты | Мультиагентный диалог | Произвольная |
| Tool calling | Нативный (ToolNode) | Через Tools | Через Tools | Function calling | Ручная реализация |
| Стриминг (SSE) | `astream_events` | Ограниченный | Нет | Нет | Ручная реализация |
| Память | MemorySaver (thread_id) | ConversationBufferMemory | Встроенная (short-term) | Нет нативной | Ручная реализация |
| Маршрутизация | Command pattern | Нет (один агент) | Task delegation | Speaker selection | Ручная реализация |
| Structured output | Pydantic (with_structured_output) | Через OutputParser | JSON | JSON | Ручная валидация |
| Контроль потока | Условные рёбра, циклы | Линейный (ReAct) | Последовательный/иерархический | Round-robin / auto | Полный контроль |
| Отладка | LangSmith трассировка | LangSmith | Логирование | Логирование | Ручная |

### Анализ альтернатив

**LangGraph** реализует агент как ориентированный граф состояний (`StateGraph`), где узлы — функции обработки, а рёбра — условные переходы. Такая архитектура обеспечивает явный контроль потока выполнения: агент может вызывать инструменты, анализировать результаты и принимать решение о следующем шаге. `MemorySaver` с `thread_id` обеспечивает сохранение контекста диалога между HTTP-запросами. Паттерн `Command` позволяет главному агенту делегировать задачи специализированному (forecast_agent) с передачей состояния.

**LangChain AgentExecutor** — предшественник LangGraph, реализующий цикл ReAct (Reasoning + Acting). Поддерживает tool calling, но имеет линейную архитектуру без условных переходов и циклов. Ограниченный стриминг: токены передаются, но промежуточные шаги агента (tool calls) не стримятся. Официально помечен как legacy в пользу LangGraph.

**CrewAI** ориентирован на мультиагентные системы с ролевыми агентами (researcher, writer, analyst). Каждому агенту назначается роль, цель и набор инструментов. Подходит для задач декомпозиции сложных workflow на роли, но избыточен для данного проекта, где достаточно двух агентов (основной + прогнозный). Отсутствие нативного SSE-стриминга ограничивает интеграцию с real-time чатом.

**AutoGen (Microsoft)** реализует мультиагентный диалог, где агенты обмениваются сообщениями в формате чата. Ориентирован на сценарии «агент-агент» (code generation + code execution), что не соответствует архитектуре «пользователь → агент → инструменты». Отсутствие нативной памяти между сессиями и SSE-стриминга ограничивает применимость.

**Custom agent loop** — ручная реализация цикла «LLM → tool call → result → LLM» без фреймворка. Обеспечивает полный контроль, но требует самостоятельной реализации: парсинга tool calls, управления состоянием, стриминга, памяти, обработки ошибок и retry-логики. Трудоёмкость разработки несоразмерна объёму ВКР.

## Обоснование выбора

**LangGraph** выбран по следующим основаниям:

1. **Граф состояний**: `StateGraph` с типизированным `AgentState` обеспечивает явную архитектуру агента — каждый узел (call_model, tools, route) имеет определённую ответственность, что упрощает отладку и расширение.

2. **Tool calling**: 5 инструментов агента (`search_hotels`, `search_events`, `get_weather`, `forecast_occupancy`, `get_statistics`) интегрированы через `ToolNode` с автоматическим маршалингом аргументов и валидацией через Pydantic-схемы.

3. **SSE-стриминг**: `astream_events` обеспечивает потоковую передачу токенов ответа и промежуточных шагов агента через Server-Sent Events, что критично для UX чата (пользователь видит ответ по мере генерации).

4. **Память**: `MemorySaver` с `thread_id` сохраняет контекст диалога между HTTP-запросами без внешнего хранилища, обеспечивая связность многоходовых диалогов.

5. **Маршрутизация**: паттерн `Command` позволяет `main_agent` делегировать запросы прогнозирования в `forecast_agent`, который формирует объяснимый прогноз с LLM-интерпретацией результатов Ensemble-модели.

6. **Мультипровайдерность**: совместимость с `langchain-mistralai`, `langchain-gigachat`, `langchain-openai` позволяет переключать LLM-провайдера через переменную окружения `LLM_PROVIDER` без изменения кода агента.
