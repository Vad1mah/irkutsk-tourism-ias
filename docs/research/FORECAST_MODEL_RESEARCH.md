# Исследование и выбор модели прогнозирования загрузки отелей
 
**Дата:** 16.02.2026

---

## 1. Постановка задачи

**Цель:** Прогнозирование загрузки отелей Иркутской области на 7-30 дней вперёд.

**Входные данные:**
- История загрузки: 37 663 записей за 323 дня
- События региона: 318 событий
- Погода: OpenMeteo API (история + прогноз)
- Праздники: holidays library + школьные каникулы

**Метрики качества:**
- RMSE (Root Mean Square Error) — основная
- MAE (Mean Absolute Error) — дополнительная

---

## 2. Обзор исследованных моделей

### 2.1 Prophet (Facebook/Meta)

**Описание:** Модель временных рядов, разработанная Facebook для бизнес-прогнозирования.

**Принцип работы:**
```
y(t) = g(t) + s(t) + h(t) + ε

где:
- g(t) — тренд (линейный или логистический)
- s(t) — сезонность (годовая, недельная)
- h(t) — эффекты праздников
- ε — шум
```

**Преимущества:**
- Автоматическое определение сезонности
- Встроенная поддержка праздников России
- Устойчивость к пропускам в данных
- Интерпретируемость компонентов

**Недостатки:**
- Не учитывает сложные нелинейные зависимости
- Требует минимум 2 года данных для годовой сезонности

### 2.2 NeuralProphet

**Описание:** Нейросетевое расширение Prophet на базе PyTorch.

**Принцип работы:**
```
Архитектура:
┌─────────────┐
│ AR Network  │ ← Авторегрессия (лаги)
├─────────────┤
│ Feed-Forward│ ← Нелинейные зависимости
├─────────────┤
│ Seasonality │ ← Фурье-компоненты
├─────────────┤
│ Covariates  │ ← Внешние переменные (погода)
└─────────────┘
```

**Преимущества:**
- Нейросетевое обучение
- Поддержка лаговых признаков
- Интеграция внешних регрессоров
- Multi-step прогнозирование

**Недостатки:**
- Требует больше данных для обучения
- Дольше обучается (~3 сек vs 0.5 сек)

### 2.3 XGBoost (Gradient Boosting)

**Описание:** Ансамбль решающих деревьев с градиентным бустингом.

**Принцип работы:**
```
F(x) = Σ fₖ(x)

где fₖ — слабые модели (деревья), обучаемые последовательно
для минимизации функции потерь.
```

**Особенность:** Требует feature engineering — ручного создания признаков.

**Наши 34 признака:**

| Категория | Признаки | Количество |
|-----------|----------|------------|
| Календарные | day_of_week, month, is_weekend, quarter... | 8 |
| Праздники | is_holiday, days_to_holiday, is_school_holiday... | 5 |
| Лаги | lag_1, lag_7, lag_14, lag_30, lag_365 | 7 |
| Rolling | mean_7, mean_30, std_7, min_7, max_7 | 5 |
| Погода | temperature, precipitation, is_good_weather | 4 |
| События | events_count, events_week, has_major_event | 3 |
| Тренд | time_index, trend | 2 |

**Преимущества:**
- Высокая точность на табличных данных
- Feature importance — объяснимость
- Быстрое обучение

**Недостатки:**
- Требует feature engineering
- Не понимает временную структуру напрямую

### 2.4 LightGBM

**Описание:** Альтернативная реализация градиентного бустинга от Microsoft.

**Отличия от XGBoost:**
- Leaf-wise рост деревьев (быстрее)
- Histogram-based split (меньше памяти)
- Лучше на больших данных

## 4. Почему Ensemble лучше?

### 4.1 Принцип работы Ensemble

```
Ensemble = Σ (wᵢ × Modelᵢ)

где wᵢ = 1 / RMSEᵢ (обратно пропорционально ошибке)
```

**Пример расчёта весов:**
```
Prophet:       w₁ = 1/5.39 = 0.185 → 21%
NeuralProphet: w₂ = 1/4.85 = 0.206 → 24%
XGBoost:       w₃ = 1/5.73 = 0.175 → 20%
LightGBM:      w₄ = 1/5.81 = 0.172 → 20%
```

### 4.2 Почему это работает?

**Теорема:** Комбинация независимых прогнозов снижает дисперсию ошибки.

```
Var(Ensemble) = (1/n²) × Σ Var(Modelᵢ)

При n=4 моделях: дисперсия уменьшается в ~4 раза
```

**Практический эффект:**
- Prophet хорошо ловит сезонность
- NeuralProphet — нелинейные зависимости
- XGBoost — влияние признаков (погода, события)
- Вместе они компенсируют недостатки друг друга

## 5. Feature Importance (что влияет на прогноз)

Результаты XGBoost показали важность признаков:

| Признак | Важность | Интерпретация |
|---------|----------|---------------|
| **rolling_min_7** | 48% | Минимум за неделю — сильный индикатор |
| **rolling_mean_7** | 11% | Средняя загрузка за неделю |
| **rolling_max_7** | 11% | Максимум за неделю |
| **lag_1** | 7% | Вчерашняя загрузка |
| **month** | 4.5% | Сезонность по месяцам |
| **events_count** | 3% | Количество событий |
| **temperature** | 2% | Погода |

**Вывод:** Rolling-статистики (последние 7 дней) — главный предиктор.

## 8. Ограничения и будущее развитие

### 8.1 Текущие ограничения

| Ограничение | Влияние | Решение |
|-------------|---------|---------|
| 1 год данных | Годовая сезонность неточна | Накопление данных |
| 1 агрегатор (101hotels) | 70-80% рынка | Достаточно для MVP |
| Нет авиатрафика | ~5% точности | API недоступен |

### 8.2 Направления развития

1. **Cascade Routing** — эскалация от простых моделей к сложным
2. **Fine-tuning** на туристическом домене
3. **A/B тестирование** с реальными пользователями
4. **Сравнение с GigaChat** для русскоязычных задач

## 9. Выводы

1. **Ensemble из 4 моделей** показывает лучший результат (RMSE 2.24 vs 4.85+ для отдельных)

2. **Rolling-статистики** — главный предиктор (48% важности), что согласуется с research

3. **LangGraph Agent** обеспечивает объяснимый AI — прогноз с обоснованием факторов

4. **Архитектура масштабируема** — легко добавить новые модели или признаки
