> **Дата актуализации:** 2026-05-03.

## Слайд 1: Титульный

**НА СЛАЙДЕ:**
- Информационно-аналитическая система мониторинга и прогнозирования туристической активности Иркутской области
- Технико-экономическое обоснование (B2B-инструмент)
- ФИО, 2026 год

**РЕЧЬ:**
Добрый день! Представляю технико-экономическое обоснование проекта — информационно-аналитическая система мониторинга рынка размещения Иркутской области. По итогам защиты отчёта по производственной практике 7 апреля 2026 года система перепозиционирована в чистый B2B-инструмент для отельеров, региональной администрации и исследователей.

---

## Слайд 2: Проблема

**НА СЛАЙДЕ:**
- Заголовок: «Проблема рынка»
- Отельеры: нет локальных RMS-метрик с учётом событий Байкала
- Администрация: нет агрегированной картины рынка по 549 КСР региона
- Исследователи: данные Росстата приходят с задержкой 6–12 месяцев
- Существующие RMS (TravelLine, Bnovo, Hotellab) — без региональной адаптации

**РЕЧЬ:**
На рынке размещения Иркутской области отсутствует специализированный инструмент аналитики. Отельеры не имеют RMS-метрик с учётом локальных событий и природной сезонности Байкала. Региональная администрация не получает оперативной картины по 549 коллективным средствам размещения. Исследователи ждут отчётности Росстата по полгода. Коммерческие RMS-системы — TravelLine, Bnovo Pricer, Hotellab — региональную специфику не учитывают.

---

## Слайд 3: Решение

**НА СЛАЙДЕ:**
- Заголовок: «Решение»
- Веб-платформа с тремя модулями:
  - Аналитика рынка: heatmap, RevPAR, Pickup/Pace
  - Прогноз спроса: ансамбль 3 ML-моделей (RMSE 3,85 п. п.)
  - AI-аналитик: бизнес-запросы через LangGraph + 6 tools
- CSV-экспорт для исследователей

**РЕЧЬ:**
Решение — веб-платформа с тремя модулями. Аналитика рынка отдаёт RMS-метрики по выбранному району и тепловую карту загрузки по дням недели и месяцам. Прогнозный модуль использует ансамбль из трёх ML-моделей и снизил RMSE до 3,85 процентных пунктов на горизонте до 14 дней. AI-аналитик на LangGraph с шестью инструментами работает с тем же ML-ядром в режиме бизнес-аналитика, не туристического консультанта. Для исследователей предусмотрен CSV-экспорт.

## Слайд 6: Технологии

**НА СЛАЙДЕ:**
- Backend: Python 3.11, FastAPI, SQLAlchemy 2.0, asyncpg
- БД: PostgreSQL 16 + Redis 7 + ChromaDB (Docker, multi-stage)
- ML: Ensemble — Prophet + NeuralProphet + XGBoost (RMSE 3,85 п. п.)
- AI: LangGraph + Mistral Large + 6 tools, MemorySaver
- Frontend: React 18, Vite, Recharts + ECharts

**РЕЧЬ:**
Backend — Python с FastAPI и асинхронным SQLAlchemy на драйвере asyncpg. Хранилище — PostgreSQL 16, Redis 7, векторный ChromaDB, всё в Docker через multi-stage сборку. Ансамбль из трёх ML-моделей — Prophet, NeuralProphet, XGBoost — со взвешиванием inverse-RMSE снизил среднеквадратичную ошибку до 3,85 процентных пунктов. AI-агент построен на LangGraph с шестью инструментами и долговременной памятью. Фронтенд — React 18 с библиотеками Recharts и ECharts.
