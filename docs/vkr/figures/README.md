## ИЗМЕНЕНИЯ ТЕКСТА ВКР В РАМКАХ ПРАВОК ДИАГРАММ (10.05.2026)

В `docs/vkr/OTCHET_PO_PRAKTIKE.md` внесены 2 точечные правки описаний рисунков, чтобы текст соответствовал упрощённым диаграммам:

### L241 (описание Рис. 6 Domain Model)
- **Было**: «трёх профильных актёров... инфраструктурные объекты (источник данных, **векторный индекс, кэш ответов**)... контроля состояния подсистемы сбора данных»
- **Стало**: «четырёх актёров — трёх профильных пользователей и технического администратора... доменные конструкции для расчёта прокси-метрик (RMS-метрика), оценки влияния событий и сегментного бенчмарка. Технические компоненты системы (кэш, векторный индекс, планировщик, журналирование) рассматриваются на диаграмме компонентов и развёртывания»
- **Причина**: Domain Model B2B v2 не содержит инфраструктурных сущностей по канону (они на Component / Deployment). Технический администратор включён в актёры.

### L262 (описание Рис. 7 Component)
- **Было**: «прикладного программного интерфейса из **семи маршрутизаторов**, сервисного слоя бизнес-логики из **девятнадцати модулей**, **восьми парсеров событий** и фоновой инфраструктуры (планировщика задач с **пятью заданиями**, пула потоков, промежуточного программного обеспечения)»
- **Стало**: «ключевые компоненты — клиентское одностраничное приложение, обратный прокси, прикладной программный интерфейс, сервисный слой, модуль прогнозирования, интеллектуальный агент, подсистему сбора данных и планировщик — с явно обозначенными интерфейсами (REST, потоковая передача серверных событий, HTTP) и зависимостями между компонентами»
- **Причина**: Component B2B v2 показывает 9 обобщённых компонентов с интерфейсами (по канону «компоненты, интерфейсы, зависимости»), без перечисления внутренних модулей кода.

## АРХИТЕКТУРНЫЕ ЗАМЕТКИ ДЛЯ БУДУЩИХ АГЕНТОВ

При редактировании любой диаграммы помнить:

1. **ChromaDB — `PersistentClient` внутри backend-контейнера**, не отдельный сервис (`backend/app/services/chroma_service.py:17`). На Deployment показан как `chroma_data` volume внутри backend.
2. **Docker Compose содержит 4 контейнера**: `postgres`, `redis`, `backend`, `frontend`. Никаких отдельных контейнеров для ChromaDB.
3. **Реальные имена файлов**: `app/main.py`, `app/scheduler.py`, `app/routers/*.py`, `app/services/*.py`, `app/parsers/*.py`. **НЕТ** файлов `rag_indexer.py`, `api.py`, `agent.py`, `forecasting.py`, `retriever.py`, `llm_client.py`, `admin_api.py`, `monitor.py`, `logger.py`.
4. **LLM провайдеры**: `Groq` → `DeepSeek` → `Mistral` (fallback chain). Нет `MiMo`, нет `OpenRouter` как primary.
5. **БД**: PostgreSQL 16 (asyncpg + SQLAlchemy 2.0). Нет YDB.
6. **ML модели**: Prophet + NeuralProphet + XGBoost (ансамбль с весами по inverse-RMSE). LightGBM — альтернативная реализация в xgboost_service.
7. **Sequence-диаграммы в ВКР**: только 2 (UC1 + UC11). В файле `sequence_diagrams.drawio` есть 6 устаревших страниц (UC2-UC7 со старой UC-нумерацией) — они НЕ используются в ВКР. Удалять/перенумеровать не требуется по решению пользователя.
