## 2. Модули системы

### 2.1 Frontend (8 страниц)

| Страница | Назначение | Ключевой функционал |
|----------|------------|---------------------|
| **Главная** | AI-ассистент | Чат с нейроаналитиком, ответы на вопросы о туризме |
| **Analytics** | Текущее состояние | Сравнение районов, графики загрузки, прогнозы |
| **События** | Календарь мероприятий | Фильтрация по типу/дате, карточки событий |
| **Forecast** | Прогнозирование | Графики цен, загрузки по месяцам, тренды |
| **Карта** | Геовизуализация | Recharts: treemap, radar, heatmap; ECharts GeoMap — на Dashboard |

### 2.2 Backend (7 модулей)

| Модуль | Файлы | Функции |
|--------|-------|---------|
| **AI-агент** | `llm_service.py`, `main_agent.py` | RAG-поиск, генерация ответов, tools |
| **Прогнозирование** | `prophet_service.py`, `neuralprophet_service.py`, `xgboost_service.py`, `ensemble_service.py` | 4 модели прогноза + ensemble |
| **Feature Engineering** | `feature_engineering.py` | 34 признака для ML-моделей |
| **Данные** | `data_service.py`, `chroma_service.py` | Работа с БД |
| **Внешние источники** | `weather_service.py`, `holidays_service.py` | Погода, праздники РФ |
| **Парсеры** | 8 парсеров в `parsers/` | Сбор данных из 8 источников |
| **Кэш** | `cache_service.py` | Redis для ускорения |

### 2.3 Парсеры данных (8 источников)

| Парсер | Источник | Тип данных | Кол-во |

## 3. Взаимодействие модулей

### 3.1 Сценарий: Пользователь спрашивает AI-ассистента

```
1. Пользователь → Frontend (Home.tsx)
   "Где лучше остановиться на Ольхоне в марте?"

2. Frontend → Backend (/api/query)
   POST запрос с текстом

3. Backend → ChromaDB
   Векторный поиск релевантных документов (отели, события)

4. Backend → Mistral AI
   Запрос с контекстом из ChromaDB + системный промпт

5. Mistral AI → Backend
   Сгенерированный ответ с рекомендациями

6. Backend → Frontend
   JSON с ответом и источниками

7. Frontend → Пользователь
   Отображение ответа в чате
```

### 3.2 Сценарий: Прогноз загрузки для отельера

```
1. Пользователь → Frontend (Situation.tsx)
   Выбирает район "Ольхонский", период 14 дней

2. Frontend → Backend (/api/forecast/ensemble)
   GET запрос с параметрами

3. Backend → PostgreSQL
   Получение исторических данных загрузки

4. Backend → Feature Engineering
   Генерация 34 признаков (лаги, погода, праздники, события)

5. Backend → 4 модели параллельно:
   • Prophet (сезонность)
   • NeuralProphet (нейросеть)
   • XGBoost (градиентный бустинг)
   • LightGBM (альтернатива)

6. Backend → Ensemble Service
   Взвешенное среднее по RMSE каждой модели

7. Backend → Frontend
   JSON с прогнозом, метриками, рекомендациями

8. Frontend → Пользователь
   График прогноза + советы по ценообразованию
```

### 3.3 Сценарий: LangGraph Agent с объяснением

```
1. Запрос на /api/forecast/explain

2. LangGraph Workflow (4 узла):
   
   [collect_data] → Сбор данных
   ├── PostgreSQL: история загрузки
   ├── OpenMeteo: погода
   ├── PostgreSQL: события
   └── Holidays: праздники РФ
   
   [run_models] → Запуск моделей
   ├── Prophet прогноз
   ├── NeuralProphet прогноз
   └── XGBoost прогноз
   
   [analyze_factors] → Анализ факторов
   ├── Feature importance из XGBoost
   ├── Влияние праздников
   ├── Влияние событий
   └── Сезонность
   
   [generate_explanation] → LLM объяснение
   └── Mistral Large генерирует текст

3. Результат:
   {
     "forecast": [...],
     "factors": ["Зимний сезон +10%", "Ice Fest +25%"],
     "recommendation": "Рекомендуем повысить цены на 15%",
     "explanation": "Прогноз учитывает..."
   }
```
