# Модель алгоритма IDEF3

## ИАС «Туризм Прибайкалья»

## Структура модели

Модель состоит из **двух сценариев** - версий декомпозиции контекстной работы "Работа с данными туризма" (номер 1):

1. **Сценарий 1 (декомпозиция 1.1)** - фоновый сбор данных (работы 1.1.2 - 1.1.9)
2. **Сценарий 2 (декомпозиция 1.2)** - обработка запроса пользователя (работы 1.2.10 - 1.2.18)

**Примечание:** Нумерация сквозная по всей модели - все номера работ уникальны.

---

## Сценарий 1: Фоновый сбор данных (декомпозиция 1.1)

**Запуск:** автоматически по расписанию (APScheduler — события 6ч, отели 2ч, погода 3ч, Telegram 1ч)

### Единицы работ (UOW)

| № | Имя работы | Описание |
|---|------------|----------|
| 1.1.2 | Запуск сбора данных | Инициализация процесса по расписанию |
| 1.1.3 | Сбор данных о событиях | asyncio.gather: irk.ru, culture38.ru, zeroevent.ru, kassir.ru (Crawl4AI), Telegram, yandex, culture_rf |
| 1.1.4 | Сбор данных о размещении | 101Hotels API (региональный режим) + Xotelo API (cross-reference) |
| 1.1.5 | Сбор данных о погоде | Open-Meteo API (прогноз + исторические) |
| 1.1.6 | Нормализация и валидация | Очистка, проверка, дедупликация по ID |
| 1.1.7 | Логирование ошибки | Запись через HealthMonitor, статистика парсеров |
| 1.1.8 | Сохранение в PostgreSQL | Batch insert в таблицы events, hotels, hotel_statistics |
| 1.1.9 | Индексация в Chroma | GigaChatEmbeddings → ChromaDB |
| 1.1.10 | Завершение сбора | Финальная работа, статистика |

### Перекрёстки

| № | Тип | Назначение |
|---|-----|------------|
| J1 | & (асинхронное И) | Разветвление: параллельный запуск сбора событий, размещения и погоды |
| J2 | & (асинхронное И) | Слияние: ожидание завершения всех сборов (asyncio.gather) |
| J3 | X (исключающее ИЛИ) | Разветвление: данные валидны / ошибка источника |
| J4 | X (исключающее ИЛИ) | Слияние: после нормализации или логирования ошибки |

### Объекты ссылок

| Тип | Имя | Описание |
|-----|-----|----------|
| OBJECT/ | irk.ru, culture38.ru, zeroevent.ru, kassir.ru, Telegram, yandex, culture_rf | Источники событий (7 парсеров) |
| OBJECT/ | 101Hotels API, Xotelo API | Источники размещения |
| OBJECT/ | Open-Meteo API | Источник погоды |
| ELAB/ | Описание J3 | Если данные валидны → Нормализация; Если ошибка → Логирование (HealthMonitor) |
| NOTE/ | Расписание | APScheduler: события 6ч, отели 2ч, погода 3ч, Telegram 1ч |

### Схема

```
                OBJECT/                    OBJECT/               OBJECT/
        irk,culture38,zeroevent,       101Hotels API,        Open-Meteo API

   1.1.2 ──► [J1 &] ─┬─► 1.1.3 ─────┐
  Запуск              │  Сбор        │
  сбора               │  событий     │
                      │  (7 парсер.) │
                      ├─► 1.1.4 ─────┤
                      │  Сбор        │
                      │  размещения  │
                      └─► 1.1.5 ─────┴─► [J2 &] ──► [J3 X] ─┬─► 1.1.6 ─────┐
                         Сбор погоды                          │ Нормализация │
                                                              │              │
                                                              └─► 1.1.7 ────┼─► [J4 X] ──► 1.1.8 ──► 1.1.9 ──► 1.1.10
                                                                 Логирование│              Сохранение Индексация Заверш.
                                                                 ошибки     │              PostgreSQL  Chroma    сбора
```

## Сценарий 2: Обработка запроса пользователя (декомпозиция 1.2)

**Запуск:** по запросу пользователя через веб-интерфейс

### Единицы работ (UOW)

| № | Имя работы | Описание |
|---|------------|----------|
| 1.2.10 | Получение запроса | Пользователь вводит вопрос |
| 1.2.11 | Поиск контекста в Chroma | RAG: поиск релевантных документов |
| 1.2.12 | Определение типа запроса | Агент классифицирует: прогноз или аналитика |
| 1.2.13 | Ensemble прогнозирование | Prophet + NeuralProphet + XGBoost → weighted average |
| 1.2.14 | Аналитика исторических данных | Выборка данных для запросов о прошлом |
| 1.2.15 | Генерация ответа (LLM) | Формирование текстового ответа |
| 1.2.16 | Визуализация результатов | Отображение графиков в React |
| 1.2.17 | Сохранение в историю | Запись в user_queries, agent_responses |
| 1.2.18 | Завершение обработки | Финальная работа, завершающая процесс |

### Перекрёстки

| № | Тип | Назначение |
|---|-----|------------|
| J5 | X (исключающее ИЛИ) | Разветвление: прогноз ИЛИ аналитика |
| J6 | X (исключающее ИЛИ) | Слияние: после прогноза или аналитики |
| J7 | & (асинхронное И) | Разветвление: визуализация И сохранение |
| J8 | & (асинхронное И) | Слияние: ожидание визуализации и сохранения |

### Объекты ссылок

| Тип | Имя | Описание |
|-----|-----|----------|
| OBJECT/ | Запрос пользователя | Входные данные от пользователя |
| OBJECT/ | Контекст из Chroma | Релевантные документы из RAG |
| OBJECT/ | Данные из PostgreSQL + события + погода | Исторические данные, календарь событий, прогноз погоды |
| ELAB/ | Описание J5 | X = Исключающее ИЛИ. Если о будущем → Прогноз; Если о прошлом → Аналитика |

## Правила создания перекрёстков (из материалов преподавателя)

1. Каждому **перекрёстку для слияния** должен предшествовать **перекрёсток для разветвления**
2. Перекрёсток для слияния **«И»** НЕ может следовать за перекрёстком для разветвления типа **синхронного или асинхронного «ИЛИ»**
3. Перекрёсток для слияния **«И»** НЕ может следовать за перекрёстком типа **исключительного «ИЛИ»**

### Проверка соответствия правилам:

| Сценарий | Разветвление | Слияние | Соответствует? |
|----------|--------------|---------|----------------|
| 1 | J1 (&) | J2 (&) | ✓ Одинаковый тип |
| 1 | J3 (X) | J4 (X) | ✓ Одинаковый тип |
| 2 | J5 (X) | J6 (X) | ✓ Одинаковый тип |
| 2 | J7 (&) | J8 (&) | ✓ Одинаковый тип |

## Нумерация IDEF3 (формат X.Y.Z)

- **X** - номер родительской работы (1 = "Работа с данными туризма")
- **Y** - версия декомпозиции (1 = фоновый сбор, 2 = обработка запроса)
- **Z** - собственный уникальный номер работы в рамках всей модели

**Пример из материалов преподавателя:**
- Декомпозиция 1.1: работы 1.1.2 - 1.1.7
- Декомпозиция 1.2: работы 1.2.12 - 1.2.17

**В нашей модели:**
- Сценарий 1 (1.1): работы **1.1.2 - 1.1.10** (9 работ)
- Сценарий 2 (1.2): работы **1.2.10 - 1.2.18** (9 работ)

Все номера **уникальны** во всей модели.

## Нотация элементов (по материалам преподавателя)

| Элемент | Форма | Описание |
|---------|-------|----------|
| UOW (единица работ) | Прямоугольник с подвалом | Имя сверху, номер в подвале слева |
| Перекрёсток | Квадрат с символом | & = И, X = Искл.ИЛИ, O = ИЛИ |
| OBJECT/ | Прямоугольник | "OBJECT/Имя объекта" |
| ELAB/ | Прямоугольник | Уточнение к перекрёстку |
| NOTE/ | Прямоугольник | Примечание |
| GOTO/ | Прямоугольник | Ссылка для цикла |
| Связь предшествования | Сплошная стрелка | Временная последовательность |
| Связь ссылки | Пунктирная линия | Связь объекта с работой |
