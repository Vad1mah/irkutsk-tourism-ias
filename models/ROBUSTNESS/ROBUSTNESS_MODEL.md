# Диаграммы анализа пригодности (Robustness)

## Назначение

Диаграмма анализа пригодности связывает диаграммы Use Case с диаграммами последовательности и классов. Она является средством санитарной проверки сценариев прецедентов.

## Типы объектов (классы, НЕ функции!)

**Важно:** Диаграмма пригодности — это диаграмма КЛАССОВ/объектов, НЕ функций. Овал (ellipse) означает функцию (Use Case), на диаграмме пригодности он НЕ используется!

| Тип | UML-форма | Именование | Описание |
|-----|-----------|------------|----------|
| Boundary | `shape=umlBoundary` ○━ | Существительное | Экраны, формы, диалоговые окна |
| Entity | `shape=umlEntity` ○̲ | Существительное | Данные из Domain Model (таблицы БД) |
| Control | `shape=umlControl` ⟳ | Глагол | Контроллеры, бизнес-логика |

## Правила связей

| Источник | Цель | Разрешено |
|----------|------|-----------|
| Актёр | Boundary | Да (с подписью действия) |
| Актёр | Control | Нет |
| Актёр | Entity | Нет |
| Boundary | Control | Да |
| Boundary | Entity | Нет (существительные не связываются) |
| Control | Control | Да |
| Control | Entity | Да |
| Entity | Entity | Нет (существительные не связываются) |

## Рекомендации (по материалам лекции)

- 2-5 контроллеров на диаграмму (не 1 и не более 10)
- Связи от актёра к Boundary подписывать действиями
- Диаграмма должна соответствовать тексту сценария Use Case
- Отражать альтернативные последовательности

## Диаграммы по Use Case

### UC1. Построить прогноз загруженности (5 контроллеров)

**Boundary:** Главная страница, Форма ввода, Область ответа, График

**Control:** Обработать запрос, Найти контекст, Построить прогноз, Сформировать ответ, Сохранить

**Entity:** Запрос, Индекс, Статистика, Событие, Прогноз, Ответ, История

**Подписи на связях:** открывает, вводит вопрос нажимает Отправить, читает ответ, просматривает

### UC2. Просмотреть справочник размещения (3 контроллера)

**Boundary:** Страница справочника, Панель фильтров, Карточка объекта

**Control:** Загрузить список, Отфильтровать, Показать детали

**Entity:** Средство размещения, Район, Тип, Номерной фонд

**Подписи на связях:** переходит, выбирает параметры, кликает на строку

### UC3. Просмотреть календарь событий (3 контроллера)

**Boundary:** Страница календаря, Фильтр типа, Карточка события

**Control:** Загрузить события, Отфильтровать, Показать детали

**Entity:** Событие, Тип события, Календарь

**Подписи на связях:** переходит, выбирает тип, кликает на событие

### UC4. Просмотреть историю запросов (2 контроллера)

**Boundary:** Страница истории, Панель диалога

**Control:** Загрузить историю, Показать диалог

**Entity:** История, Запрос, Ответ

**Подписи на связях:** переходит, кликает на запрос

### UC5. Настроить источники данных (3 контроллера)

**Boundary:** Панель админа, Форма редактирования

**Control:** Загрузить источники, Сохранить, Проверить доступность

**Entity:** Источник данных

**Подписи на связях:** переходит, редактирует настройки

### UC6. Просмотреть логи системы (3 контроллера)

**Boundary:** Страница логов, Фильтры

**Control:** Загрузить логи, Отфильтровать, Экспортировать

**Entity:** Лог системы

**Подписи на связях:** переходит, задаёт параметры

### UC7. Выполнить сбор данных - фоновый процесс (4 контроллера)

**Boundary:** irk.ru, culture38.ru, 101Hotels (внешние источники данных)

**Control:** Запустить сбор, Парсить события, Парсить размещение, Сохранить в БД

**Entity:** ИсточникДанных, Событие, Средство размещения, Индекс

**Подписи на связях:** по расписанию, парсит, сохраняет, индексирует

## Связь с другими моделями

| Модель | Связь |
|--------|-------|
| Use Case | Каждая диаграмма соответствует одному UC |
| Domain Model | Entity объекты = объекты предметной области |
| UI | Boundary объекты = экраны интерфейса |
| IDEF3 | Control объекты = единицы работ |
