# Модель предметной области IDEF1X

## ИАС «Туризм Прибайкалья»

## Источники данных для модели

Модель разработана на основе:
1. Существующий парсер 101hotels (`101hotel_parser/main.py`)
2. Курсовая работа Исполатов В.П.
3. Структура таблиц PostgreSQL 16

## Перечень сущностей

### Существующие (из курсовой работы):
1. Средство размещения (hotels)
2. Номер (rooms_data)
3. Статистика загруженности (hotel_statistics)

### Справочники:
4. Район (districts)
5. Источник данных (data_sources)

### Новые (для дипломной работы):
6. Событие (events)
7. Прогноз (forecasts)
8. Запрос пользователя (query_history)
9. Ответ агента (agent_responses)

## Схема связей

```
┌──────────────┐                              ┌──────────────┐
│    Район     │                              │   Источник   │
│  (districts) │                              │ (data_source)│
│ district_id  │                              │  source_id   │
└──────┬───────┘                              └───────┬──────┘
       │ (неидент.)                                   │ (неидент.)
       ╎                                              ╎
       ╎                                              ╎
       ▼                                              ▼
┌────────────────────────────┐                ┌──────────────┐
│   Средство размещения      │╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌│   Событие    │
│   (hotels)            │                │   (events)   │
│   id (PK)                  │                │  event_id    │
│   district_id (FK)         │                │  source_id   │
│   source_id (FK)           │                └──────────────┘
└──────────┬─────────────────┘
           │ (идент.)
     ┌─────┼─────┬───────────────┐
     │     │     │               │
     ▼     ▼     ▼               │
┌────────┐ ┌────────┐  ┌────────┐
│ Номер  │ │Статист.│  │Прогноз │
│rooms   │ │hotels_ │  │forec.  │
│_data   │ │statis. │  │        │
│id+date │ │id+date │  │id+date │
└────────┘ └────────┘  └────────┘


┌────────────────────┐
│ Запрос пользователя│
│ query_history       │
│ query_id (PK)      │
└─────────┬──────────┘
          │ (идент.)
          ▼
┌────────────────────┐
│   Ответ агента     │
│ agent_responses    │
│ query_id (PK, FK)  │
└────────────────────┘
```

Пунктирные линии (╌╌╌) - неидентифицирующие связи
Сплошные линии - идентифицирующие связи

## Типы связей

### Идентифицирующие (сплошная линия)

| Родитель | Потомок | Пояснение |
|----------|---------|-----------|
| Средство размещения | Номер | FK входит в PK номера |
| Средство размещения | Статистика | FK входит в PK статистики |
| Средство размещения | Прогноз | FK входит в PK прогноза |
| Запрос пользователя | Ответ агента | FK = PK ответа |

### Неидентифицирующие (пунктирная линия)

| Родитель | Потомок | Пояснение |
|----------|---------|-----------|
| Район | Средство размещения | district_id - просто атрибут, не часть PK |
| Источник данных | Средство размещения | source_id - просто атрибут, не часть PK |
| Источник данных | Событие | source_id - просто атрибут, не часть PK |

## Мощность связей

| Связь | Мощность | Обозначение |
|-------|----------|-------------|
| Средство размещения - Номер | 1:N | ● у Номера |
| Средство размещения - Статистика | 1:N | ● у Статистики |
| Средство размещения - Прогноз | 1:N | ● у Прогноза |
| Запрос - Ответ | 1:1 | Z у Ответа |

## Отличие от примера однокурсника

У однокурсника ВСЕ связи пунктирные (неидентифицирующие).

В нашей модели - **смешанный подход**:
- **4 связи ИДЕНТИФИЦИРУЮЩИЕ** (сплошные) - зависимые сущности
- **3 связи НЕИДЕНТИФИЦИРУЮЩИЕ** (пунктирные) - справочные сущности
