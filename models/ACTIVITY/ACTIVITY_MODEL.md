# Диаграммы деятельности (Activity Diagrams)

## Общее описание

Диаграммы деятельности описывают последовательность действий для каждого бизнес-процесса системы с использованием дорожек (swimlanes).

## БП1: Сбор и обновление данных о туризме

**Дорожки:** Планировщик, Парсер, PostgreSQL 16, Chroma

**Последовательность действий:**
1. Запустить сбор по расписанию (Планировщик)
2. Fork: параллельный парсинг
   - Парсить данные о средствах размещения (Парсер)
   - Парсить данные о событиях (Парсер)
3. Join: объединение потоков
4. Decision: Данные валидны?
   - [нет] Логировать ошибку
   - [да] Сохранить данные в таблицы (PostgreSQL 16)
5. Сформировать эмбеддинги (Chroma)
6. Обновить индекс (Chroma)
7. Записать лог успешного сбора (Планировщик)

## БП2: Взаимодействие с пользователем

**Дорожки:** Пользователь, Веб-интерфейс, FastAPI

**Последовательность действий:**
1. Открыть главную страницу (Пользователь)
2. Отобразить форму чата (Веб-интерфейс)
3. Ввести вопрос на естественном языке (Пользователь)
4. Нажать кнопку Отправить (Пользователь)
5. Отправить запрос на API (Веб-интерфейс)
6. Принять запрос и валидировать (FastAPI)
7. Decision: Запрос валиден?
   - [нет] Вернуть ошибку 400 -> Отобразить ошибку
   - [да] Передать запрос AI-агенту
8. Прочитать ответ (Пользователь)

## БП3: Анализ данных и формирование ответа

**Дорожки:** FastAPI, AI-агент, RAG (Chroma), Prophet, PostgreSQL 16

**Последовательность действий:**
1. Принять запрос от пользователя (FastAPI)
2. Анализировать текст запроса (AI-агент)
3. Decision: Запрос о будущем?
   - [нет] Сформировать эмбеддинг запроса (RAG) -> Найти релевантные документы (RAG)
   - [да] Загрузить исторические данные (PostgreSQL 16) -> Построить прогноз загруженности (Prophet) -> Учесть календарь событий (Prophet)
4. Join: объединение контекста и прогноза
5. Сформировать промпт с контекстом (AI-агент)
6. Сгенерировать ответ LLM (AI-агент)
7. Сохранить запрос и ответ (PostgreSQL 16)
8. Вернуть ответ пользователю (FastAPI)

## Соответствие другим моделям

- **IDEF3 (1.1.X):** БП1 соответствует сценарию "Фоновый сбор данных"
- **IDEF3 (1.2.X):** БП2 и БП3 соответствуют сценарию "Обработка запроса пользователя"
- **Use Case:** UC1, UC2 реализуются через БП2 и БП3
- **Robustness:** Control-объекты отражены как Activities в соответствующих дорожках
