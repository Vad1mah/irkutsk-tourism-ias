# Сценарии вариантов использования

## UC1. Построить прогноз загруженности

**Краткое описание:** Пользователь получает прогноз загруженности туристической инфраструктуры, задавая вопрос на естественном языке.

**Актёры:** Пользователь

**Предусловия:**
- Система доступна
- Поисковый индекс содержит актуальные данные
- Модель прогнозирования обучена на исторических данных

**Постусловия:**
- Прогноз отображён пользователю
- Запрос и ответ сохранены в историю

**Главная последовательность:**
1. Пользователь открывает главную страницу системы
2. Система отображает форму чата с полем ввода
3. Пользователь вводит вопрос о загруженности на русском языке (include: Ввести вопрос)
4. Пользователь нажимает кнопку отправки
5. Система ищет релевантный контекст в векторной базе (include: Поиск контекста RAG)
6. Система определяет тип запроса (прогноз/аналитика)
7. Система генерирует текстовый ответ с помощью LLM (include: Генерация ответа LLM)
8. Система отображает результат в окне чата
9. Система сохраняет запрос и ответ в базу данных

**Альтернативные последовательности:**

*6a. Запрос о будущем периоде (extend: Построить прогноз Prophet):*
- 6a.1. Система определяет, что запрос связан с будущим периодом
- 6a.2. Система строит прогноз загруженности с использованием Prophet
- 6a.3. Система добавляет прогнозные данные в контекст для LLM
- 6a.4. Переход к шагу 7

*6b. Запрос об историческом периоде:*
- 6b.1. Система определяет, что запрос связан с прошлым периодом
- 6b.2. Система выполняет аналитику исторических данных из YDB
- 6b.3. Переход к шагу 7

*8a. Ответ содержит числовые данные (extend: Визуализировать на графике):*
- 8a.1. Система формирует данные для графика
- 8a.2. Система отображает интерактивный график под текстом ответа
- 8a.3. Переход к шагу 9

*8b. Найден контекст из источников (extend: Показать источники информации):*
- 8b.1. Система формирует список использованных источников
- 8b.2. Система отображает ссылки на источники под ответом
- 8b.3. Переход к шагу 9

*5a. Релевантная информация не найдена:*
- 5a.1. Система использует общие знания для формирования ответа
- 5a.2. Система добавляет предупреждение о возможной неточности
- 5a.3. Переход к шагу 7

*6a-err. Ошибка при построении прогноза:*
- 6a-err.1. Система фиксирует ошибку в журнале
- 6a-err.2. Система формирует ответ без прогнозных данных
- 6a-err.3. Переход к шагу 7

**Ассоциации:**
- Пользователь взаимодействует с формой чата
- Страница чата связана с прецедентом Просмотреть историю запросов

**Главная последовательность:**
1. Пользователь переходит в раздел "Справочник размещения"
2. Система загружает список средств размещения из базы данных
3. Система отображает таблицу с основными характеристиками (название, район, тип, рейтинг)
4. Пользователь просматривает список

**Альтернативные последовательности:**

*3a. Применить фильтр (extend: Фильтровать по параметрам):*
- 3a.1. Пользователь выбирает район из выпадающего списка
- 3a.2. Пользователь выбирает тип размещения
- 3a.3. Пользователь задаёт диапазон рейтинга
- 3a.4. Система применяет фильтры и обновляет таблицу
- 3a.5. Переход к шагу 4

*4a. Просмотреть детали объекта (extend: Просмотреть детали объекта):*
- 4a.1. Пользователь кликает на строку таблицы
- 4a.2. Система открывает карточку средства размещения
- 4a.3. Система отображает полную информацию: адрес, контакты, услуги, фото
- 4a.4. Пользователь закрывает карточку и возвращается к списку

*4b. Показать на карте (extend: Показать на карте):*

- 4b.2. Система отображает карту с маркерами средств размещения
- 4b.3. Пользователь взаимодействует с картой
- 4b.4. Переход к шагу 4

*2a. Данные не найдены:*

- 2a.2. Система предлагает обновить страницу
- 2a.3. Сценарий завершается

**Ассоциации:**
- Пользователь взаимодействует со страницей справочника
- Карточка объекта связана с данными о средстве размещения


## UC3. Просмотреть календарь событий

**Краткое описание:** Пользователь просматривает предстоящие и прошедшие события региона.

**Актёры:** Пользователь

**Предусловия:**
- Система доступна
- База данных содержит информацию о событиях

**Постусловия:**
- Пользователь получил информацию о событиях

**Главная последовательность:**
1. Пользователь переходит в раздел "Календарь событий"
2. Система определяет текущий месяц
3. Система загружает события за текущий месяц из базы данных
4. Система отображает календарь с отметками дней, имеющих события
5. Пользователь выбирает дату на календаре
6. Система отображает список событий на выбранную дату

**Альтернативные последовательности:**

*4a. Выбрать другой период (extend: Выбрать другой период):*
- 4a.1. Пользователь нажимает стрелки навигации
- 4a.2. Система загружает события за выбранный месяц
- 4a.3. Система обновляет отображение календаря
- 4a.4. Переход к шагу 5

*5a. Фильтр по типу события (extend: Фильтровать по типу события):*
- 5a.1. Пользователь выбирает тип события (концерт, выставка, фестиваль, спорт)
- 5a.2. Система применяет фильтр
- 5a.3. Система обновляет отметки на календаре
- 5a.4. Переход к шагу 5

*6a. Просмотреть детали события (extend: Просмотреть детали события):*
- 6a.1. Пользователь кликает на событие в списке
- 6a.2. Система открывает карточку события
- 6a.3. Система отображает: название, дату, время, место, описание, источник
- 6a.4. Пользователь закрывает карточку и возвращается к календарю

*3a. События не найдены:*
- 3a.1. Система отображает пустой календарь
- 3a.2. Система показывает сообщение "Событий на этот месяц нет"
- 3a.3. Переход к шагу 4

**Ассоциации:**
- Пользователь взаимодействует со страницей календаря
- Карточка события связана с данными из таблицы events

- Настройки источников данных обновлены

1. Администратор переходит в раздел "Настройки"
2. Администратор выбирает пункт "Источники данных"
3. Система загружает список источников из базы данных
4. Система отображает таблицу источников (название, URL, статус, последний сбор)
5. Администратор просматривает информацию

**Альтернативные последовательности:**

*5a. Редактировать настройки (extend: Редактировать настройки):*

- 5a.2. Система открывает форму редактирования

- 5a.7. Система отображает подтверждение

*5b. Проверить доступность (extend: Проверить доступность):*

- 5b.2. Система отправляет тестовый запрос к источнику
- 5b.3. Система отображает результат проверки (доступен/недоступен)

**Ассоциации:**

## UC7. Выполнить сбор данных

**Краткое описание:** Планировщик запускает автоматический сбор данных из внешних источников.

**Актёры:** Планировщик (GitHub Actions)

**Предусловия:**
- Наступило запланированное время запуска (ежедневно в 03:00 UTC)
- Источники данных настроены и активны

**Постусловия:**
- Данные в базе обновлены
- Поисковый индекс обновлён
- Результат записан в журнал

**Главная последовательность:**
1. Планировщик запускает workflow сбора данных
2. Система инициализирует подключение к базе данных
3. Система выполняет сбор событий с сайта irk.ru/afisha (include)
4. Система выполняет сбор событий с сайта culture38.ru (include)
5. Система выполняет сбор данных о средствах размещения через 101Hotels API (include)
6. Система сохраняет собранные данные в базу данных
7. Система обновляет поисковый индекс новыми данными (include)
8. Система записывает результат в журнал (количество записей, время выполнения)
9. Планировщик завершает workflow со статусом "успех"

**Альтернативные последовательности:**

*3a-5a. Ошибка при сборе из источника:*
- Xa.1. Система фиксирует ошибку в журнале с уровнем WARNING
- Xa.2. Система продолжает сбор из следующего источника
- Xa.3. Переход к следующему шагу

*6a. Ошибка записи в базу данных:*
- 6a.1. Система выполняет повторную попытку (до 3 раз)
- 6a.2. При неудаче система фиксирует ошибку с уровнем ERROR
- 6a.3. Переход к шагу 8

*8a. Критическая ошибка (extend: Уведомить администратора):*
- 8a.1. Система определяет критичность ошибки (все источники недоступны или ошибка БД)
- 8a.2. Система отправляет уведомление администратору
- 8a.3. Планировщик завершает workflow со статусом "ошибка"

**Ассоциации:**
- Планировщик взаимодействует с системой автоматически
- Сбор данных связан с источниками данных из настроек (UC5)
- Результаты сбора отображаются в логах (UC6)
