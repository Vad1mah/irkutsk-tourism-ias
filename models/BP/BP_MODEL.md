# Диаграмма бизнес-процессов (Erikson-Penker)

## Нотация

Используется расширение UML — диаграмма Erikson-Penker, применяемая в Enterprise Architect для моделирования бизнес-процессов.

### Элементы нотации

| Элемент | Обозначение | Описание |
|---------|-------------|----------|
| «event» | Параллелограмм | Событие, инициирующее процесс |
| «information» | Прямоугольник | Информация, необходимая для процесса |
| «resource» | Прямоугольник | Ресурсы (ПО, оборудование) |
| «goal» | Прямоугольник | Цель процесса |
| «output» | Прямоугольник | Результат процесса |

## Контекстная диаграмма

**Центральный процесс:** Информационно-аналитическая поддержка B2B-сегмента туристической отрасли Иркутской области.

### Стейкхолдеры (B2B)

| Стейкхолдер | Что инициирует | Что получает на выходе |
|-------------|----------------|------------------------|
| **Отельер** | Запрос на прогноз загрузки своего объекта, расчёт RMS-метрик, анализ влияния событий | Прогноз с CI-bands, RevPAR / ADR / Occupancy / Pickup / Pace, рекомендации по тарифам |
| **Администратор региона** | Запрос на агрегированную аналитику по 15 районам, мониторинг событийной активности | Heatmap по районам, рейтинг RevPAR, сводный отчёт по рынку средств размещения |
| **Исследователь** | Запрос на сравнение моделей и выгрузку данных | CSV-экспорт (occupancy / events / hotels), методология расчёта метрик и веса Ensemble |
| **Технический администратор** | Управление источниками данных, мониторинг здоровья | Состояние парсеров, логи, метрики health-checks |
| **Планировщик (APScheduler)** | Срабатывание по расписанию | Обновлённые данные в PostgreSQL и ChromaDB |

### Входные элементы

**«event»:**
- Запрос отельера / администратора / исследователя на B2B-аналитику
- Срабатывание планировщика (события 6ч, отели 2ч, погода 3ч, Telegram 1ч)
- Действия технического администратора (запуск парсера, изменение настроек)

**«information»:**
- Данные о средствах размещения (~370 гостиниц + 179 санаториев)
- События региона из 8 источников парсинга
- Исторические данные загрузки (`hotel_statistics`)
- Погодные данные Open-Meteo
- История цен и доступных номеров

**«resource»:**
- PostgreSQL 16 (основное хранилище)
- Redis 7 (кэш прогнозов и RMS-агрегатов, TTL 30 мин)
- ChromaDB (RAG, 629+ документов)
- AI-агент (LangGraph + 6 tools + Mistral Large)
- Ensemble прогнозирование (Prophet + NeuralProphet + XGBoost через `executor.run_sync`)
- FastAPI backend (7 роутеров, 59 endpoints)
- React 18 + Vite 7 frontend (8 страниц)

### Выходные элементы

**«goal»:**
- Обеспечение бизнес-решений в области управления загрузкой средств размещения и регионального ценообразования через прогноз спроса и расчёт RMS-метрик.

**«output»:**
- Прогноз загрузки объекта / района с CI-bands (`/api/forecast/ensemble`)
- RMS-метрики: RevPAR, ADR, Occupancy %, Pickup, Pace (`/api/analytics/revenue-summary`, `/api/analytics/pickup-pace`)
- Региональная аналитика: heatmap, рейтинг RevPAR, сводка по 15 районам
- Impact-оценка событий на загрузку (`/api/analytics/events-impact`)
- CSV-экспорт данных для исследователей (`/api/analytics/export?type=...`)
- Аналитический ответ AI-агента (B2B system prompt)

## Декомпозиция

### Процесс 1: Сбор и обновление данных о туристическом рынке

| Элемент | Значение |
|---------|----------|
| «event» | Срабатывание планировщика APScheduler |
| «information» | Внешние API (101Hotels, Xotelo, Open-Meteo), 8 парсеров событий, Telegram-каналы |
| «resource» | PostgreSQL 16, ChromaDB, AIExtractor, AntiDetection, HealthMonitor |
| «goal» | Актуальные данные о средствах размещения и событиях с пометкой источника и расчётом impact |
| «output» | Обновлённые таблицы `hotels`, `hotel_statistics`, `events`, `weather`; переиндексированный векторный индекс ChromaDB |

### Процесс 2: Обслуживание B2B-запросов

| Элемент | Значение |
|---------|----------|
| «event» | Отельер / администратор / исследователь обращается к системе через UI или API |
| «information» | Параметры запроса (объект, район, диапазон дат, тип данных, горизонт) |
| «resource» | FastAPI router, middleware/rate_limit, B2B-эндпоинты, AI-агент (LangGraph) |
| «goal» | Удобный ввод параметров и получение структурированного ответа в формате, пригодном для бизнес-решения |
| «output» | Структурированный JSON / CSV / визуализация (Recharts, ECharts) |

### Процесс 3: Анализ данных и формирование B2B-результата

| Элемент | Значение |
|---------|----------|
| «event» | Поступление параметризованного запроса на прогноз / RMS / экспорт |
| «information» | Данные PostgreSQL (`hotel_statistics`, `events`, `hotels`), кэш Redis, индекс ChromaDB |
| «resource» | Ensemble (Prophet + NeuralProphet + XGBoost), feature_engineering (38 признаков), AI-агент (Mistral Large), сервис расчёта RMS-метрик, сервис экспорта CSV |
| «goal» | Качественный анализ, точный прогноз и воспроизводимые метрики для B2B-сегментов |
| «output» | Прогноз с CI-bands, RMS-метрики, impact-оценка событий, региональная сводка, CSV-выгрузка, ответ AI-агента |

### Процесс 4: Администрирование и мониторинг (вспомогательный)

| Элемент | Значение |
|---------|----------|
| «event» | Действие технического администратора (изменение настроек парсера, запуск переиндексации, просмотр логов) |
| «information» | Конфигурация парсеров, логи Python logging, метрики HealthMonitor |
| «resource» | Защищённые `/api/parser/*` эндпоинты с `X-API-Key`, healthcheck-агрегатор |
| «goal» | Поддержка работоспособности системы и качества входных данных |
| «output» | Корректные настройки источников, нотификации об ошибках, отчёты о сборе |

## Связи между процессами

- Выход процесса 1 (обновлённые данные в PostgreSQL и ChromaDB) используется как «information» для процесса 3 (Ensemble прогноз и RMS-расчёты).
- Выход процесса 2 (структурированный запрос) инициирует процесс 3.
- Процесс 4 обеспечивает корректность входных данных для процесса 1 (через настройки парсеров) и наблюдаемость процесса 3 (через логи и health-checks).
- Кэш Redis служит «короткой памятью» между процессами 3 и 2 (повторные запросы за 30 минут отдаются мгновенно).
